# Security Policy

Report vulnerabilities in the public application, local tools, or deployment configuration privately. On GitHub, open **Security and quality**, then **Advisories**, and select **Report a vulnerability** if available. [GitHub private reporting instructions](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately)

If private reporting is unavailable, use a private channel listed by the repository owner. If no channel is listed, ask for one in an issue without describing the vulnerability.

In a private report, identify the affected component or version, describe the potential impact, and share only the evidence needed for maintainers to assess it. Use sanitized examples and withhold credentials, review-room codes, private research data, and personal information. Coordinate disclosure with the maintainers so they can assess and address the report.

For ordinary software issues and scientific corrections, use the templates in [the contribution guide](CONTRIBUTING.md).
